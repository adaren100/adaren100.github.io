**[Clay helps sales teams win with Codex and ChatGPT](https://openai.com/business/customer-stories/clay-plugins-openai)** — _OpenAI · Nov 24_

**Main takeaway:** A customer story: Clay, a "self-learning revenue engine," runs its research and go-to-market agents on GPT‑6 models and ships Codex and ChatGPT plugins so sales reps get that customer context inside the tools they already have open. The interesting part is the model-tiering: GPT‑6 Sol as the default, GPT‑6 Astra for the hard tasks, GPT‑6 Luna for cost-sensitive work, all behind one Responses API.

**Main methods:**
- **Three model tiers behind one interface.** Clay uses GPT‑6 Sol as its primary model, GPT‑6 Astra for harder tasks, and GPT‑6 Luna for cost-sensitive work. "Having the same Responses API across the different price points is something that's super appealing to us with OpenAI models," says Jeff.
- **Agents do enrichment, not just retrieval.** Users build lists of companies and people, then let agents enrich those records; OpenAI models power Claygent's research, qualification, enrichment, and signal detection.
- **An agent that coordinates other agents.** On top of the task agents sits one that helps users build workflows and orchestrate Clay's other agents.
- **Meet reps where they already work.** The Codex integration lets builders create and run go-to-market plays, while reps pull data to research an account or size up a deal; the ChatGPT plugin brings the same customer data into ChatGPT. Jeff on the latter: "It's been a big success."
- **Closing the loop on Clay's own engineering.** Jeff says GPT‑6 Astra changed how he builds software because it writes the code, adds tests, actually runs them, tests the feature, records it, and uploads that to the PR — replacing manual feature-checking he used to do himself.
- **Voice is the next step.** Clay sees GPT‑Live‑1 as a way to drive Clay and Codex by voice, and is building inbound sales development features where an agent walks a prospect through a product.

**[Clay 把 GPT‑6 塞进销售流程，顺手做了 Codex 和 ChatGPT 插件](https://openai.com/business/customer-stories/clay-plugins-openai)** — _OpenAI · 11月24日_

**Main takeaway:** 又一篇客户案例：Clay 自称是个"会自我学习的收入引擎"，底下跑调研和 go-to-market 的 agent 全靠 GPT‑6，还做了 Codex 和 ChatGPT 插件，让销售不用切工具就能拿到客户信息。比较值得看的是他们分档用模型这件事：默认用 GPT‑6 Sol，难的活交给 GPT‑6 Astra，对成本敏感的走 GPT‑6 Luna，三档都挂在同一个 Responses API 后面。

**Main methods:**
- **三档模型，一个接口。** 主力是 GPT‑6 Sol，难任务上 GPT‑6 Astra，成本敏感的活给 GPT‑6 Luna。Jeff 说，不同价位能共用同一套 Responses API，这点对他们吸引力特别大。
- **agent 干的是 enrichment，不只是查资料。** 用户先把公司和人拉成名单，再让 agent 去补全这些记录；Claygent 的调研、qualification、enrichment、signal detection 全是 OpenAI 模型在跑。
- **上面还有个 agent 管其他 agent。** 任务层的 agent 之上，另有一个专门帮用户搭 workflow、调度 Clay 其他 agent 的角色。
- **人在哪就把能力铺到哪。** Codex 那边给的是"搭并跑 go-to-market play"的能力，销售顺手就能拉数据研究客户、判断一笔单子；ChatGPT 插件则把同一份客户数据带进 ChatGPT。Jeff 对后者的评价是"效果很好"。
- **他们自己写代码也闭环了。** Jeff 说 GPT‑6 Astra 直接改变了他的开发方式：写代码、补 test、真的把 test 跑起来、验功能、记录下来再传到 PR 里，以前他大把时间都花在手动验功能上。
- **下一步是语音。** Clay 把 GPT‑Live‑1 看成用语音操作 Clay 和 Codex 的入口，现在在做 inbound sales 的功能，让 agent 直接给潜在客户演示产品。
